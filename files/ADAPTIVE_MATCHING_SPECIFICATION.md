## OVERVIEW

### The Adaptive Matching Philosophy

**Core Principle:**
> "Matching services ALWAYS work with just core fields (date, amount, description), but become SMARTER and MORE ACCURATE when optional fields are available."

### Three-Tier Field Strategy

```
┌─────────────────────────────────────────────────────────────┐
│ TIER 1: CORE FIELDS (Mandatory)                            │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ • Date                                                       │
│ • Amount                                                     │
│ • Description                                                │
│                                                              │
│ Role: PRIMARY matching basis (always used)                  │
│ Weight: 70-80% of total confidence score                    │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ TIER 2: ENHANCEMENT FIELDS (Optional - Boost Accuracy)     │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ • Reference Number                                           │
│ • Payer/Payee Name                                          │
│ • Currency                                                   │
│                                                              │
│ Role: CONFIDENCE BOOSTERS (add 10-20% to score)            │
│ Impact: Higher match certainty, fewer false positives       │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ TIER 3: SAFETY FIELDS (Optional - Prevent Errors)          │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ • Transaction Type (Credit/Debit)                           │
│ • Running Balance                                            │
│                                                              │
│ Role: ERROR PREVENTION (veto incorrect matches)             │
│ Impact: Never match credit to debit, validate balance logic │
└─────────────────────────────────────────────────────────────┘
```

## MATCHING SERVICE ADAPTIVE LOGIC

### Example: MT-02 (Near-Exact Match Service)

#### Base Implementation (Core Fields Only)

```python
class NearExactMatchService:
    
    def find_matches(self, bank_txns, ledger_pool, thresholds, field_profile):
        """
        Adaptive matching that uses available fields intelligently
        """
        matches = []
        
        # Extract field availability from profile
        has_bank_ref = field_profile['bank']['optional_fields']['ref_number']['present']
        has_ledger_ref = field_profile['ledger']['optional_fields']['ref_number']['present']
        has_bank_txn_type = field_profile['bank']['optional_fields']['txn_type']['present']
        has_ledger_txn_type = field_profile['ledger']['optional_fields']['txn_type']['present']
        has_ledger_payer = field_profile['ledger']['optional_fields']['payer_payee']['present']
        
        # Get usefulness scores (how reliable each field is)
        ref_usefulness = field_profile['compatibility_analysis']['ref_number']['matching_potential']
        
        for bank_txn in bank_txns:
            for ledger_txn in ledger_pool:
                
                # ═══════════════════════════════════════════════════════
                # TIER 1: CORE FIELD MATCHING (Always Applied)
                # ═══════════════════════════════════════════════════════
                
                date_score = self._fuzzy_date_match(
                    bank_txn.date, 
                    ledger_txn.date, 
                    thresholds.date_tolerance
                )
                
                amount_score = self._fuzzy_amount_match(
                    bank_txn.amount,
                    ledger_txn.amount,
                    thresholds.amount_tolerance
                )
                
                desc_score = self._fuzzy_text_match(
                    bank_txn.description,
                    ledger_txn.description,
                    thresholds.description_similarity
                )
                
                # Base score from core fields (70% weight)
                base_score = (
                    date_score * 0.25 +
                    amount_score * 0.30 +
                    desc_score * 0.15
                )  # Total: 0.70
                
                match_basis = ["date", "amount", "description"]
                
                # ═══════════════════════════════════════════════════════
                # TIER 2: ENHANCEMENT FIELDS (Conditional Boost)
                # ═══════════════════════════════════════════════════════
                
                enhancement_score = 0.0
                
                # Reference Number Matching (if available in BOTH)
                if has_bank_ref and has_ledger_ref:
                    if bank_txn.ref_number and ledger_txn.ref_number:
                        ref_match = self._fuzzy_reference_match(
                            bank_txn.ref_number,
                            ledger_txn.ref_number
                        )
                        
                        if ref_match:
                            if ref_usefulness == "HIGH":
                                enhancement_score += 0.20  # Strong boost
                            else:
                                enhancement_score += 0.10  # Moderate boost
                            
                            match_basis.append("ref_number")
                
                # Payer/Payee Matching (if available in ledger)
                if has_ledger_payer:
                    if ledger_txn.payer_payee:
                        # Try to find payer name in bank description
                        payer_in_desc = self._find_entity_in_text(
                            ledger_txn.payer_payee,
                            bank_txn.description
                        )
                        
                        if payer_in_desc:
                            enhancement_score += 0.05  # Small boost
                            match_basis.append("payer_in_description")
                
                # ═══════════════════════════════════════════════════════
                # TIER 3: SAFETY CHECKS (Veto Logic)
                # ═══════════════════════════════════════════════════════
                
                veto = False
                veto_reason = None
                
                # Transaction Type Safety (if available in BOTH)
                if has_bank_txn_type and has_ledger_txn_type:
                    if bank_txn.txn_type and ledger_txn.txn_type:
                        bank_type = self._normalize_txn_type(bank_txn.txn_type)
                        ledger_type = self._normalize_txn_type(ledger_txn.txn_type)
                        
                        if bank_type != ledger_type:
                            veto = True
                            veto_reason = "transaction_type_mismatch"
                
                # ═══════════════════════════════════════════════════════
                # FINAL SCORE CALCULATION
                # ═══════════════════════════════════════════════════════
                
                if veto:
                    final_score = 0.0
                    confidence = 0.0
                else:
                    final_score = base_score + enhancement_score
                    confidence = min(final_score, 1.0)
                
                # Only keep candidates above threshold
                if confidence >= thresholds.min_confidence:
                    matches.append({
                        'bank_id': bank_txn.id,
                        'ledger_id': ledger_txn.id,
                        'confidence': confidence,
                        'scores': {
                            'date': date_score,
                            'amount': amount_score,
                            'description': desc_score,
                            'enhancement': enhancement_score,
                            'base': base_score
                        },
                        'match_basis': match_basis,
                        'veto': veto,
                        'veto_reason': veto_reason,
                        'reasoning': self._generate_reasoning(
                            match_basis, 
                            confidence, 
                            veto_reason
                        )
                    })
        
        # Return with field usage statistics
        return {
            'candidates': matches,
            'field_usage': {
                'ref_number_matched': sum(1 for m in matches if 'ref_number' in m['match_basis']),
                'payer_used': sum(1 for m in matches if 'payer_in_description' in m['match_basis']),
                'txn_type_vetoed': sum(1 for m in matches if m['veto']),
                'avg_confidence': sum(m['confidence'] for m in matches) / len(matches) if matches else 0
            }
        }
```

### Weight Adjustment Logic

```python
def calculate_dynamic_weights(field_profile):
    """
    Adjust scoring weights based on field availability and quality
    """
    weights = {
        'date': 0.30,
        'amount': 0.40,
        'description': 0.30
    }
    
    # If reference numbers are highly reliable, redistribute weights
    ref_potential = field_profile['compatibility_analysis']['ref_number']['matching_potential']
    ref_usefulness = field_profile['bank']['optional_fields']['ref_number']['usefulness_score']
    
    if ref_potential == "HIGH" and ref_usefulness > 0.9:
        # Reference numbers are very reliable - give them more weight
        weights['date'] = 0.20
        weights['amount'] = 0.30
        weights['description'] = 0.15
        weights['ref_number'] = 0.35
    
    elif ref_potential == "MEDIUM":
        # Reference numbers somewhat reliable
        weights['date'] = 0.25
        weights['amount'] = 0.30
        weights['description'] = 0.20
        weights['ref_number'] = 0.15
        weights['payer_boost'] = 0.10
    
    # If payer/payee available in ledger, allocate small weight
    if field_profile['ledger']['optional_fields']['payer_payee']['present']:
        payer_usefulness = field_profile['ledger']['optional_fields']['payer_payee']['usefulness_score']
        if payer_usefulness > 0.8:
            # Reduce other weights slightly to make room
            weights['description'] -= 0.05
            weights['payer_boost'] = 0.05
    
    return weights
```

## LEARNING MODULE IMPACT

### 1. Field Effectiveness Tracking

The Learning Service tracks which fields are most effective for matching:

```python
class LearningService:
    
    def record_user_action(self, user_action):
        """
        Track which fields led to successful matches
        """
        # Extract field comparison
        suggested_match = user_action['rejected_suggestion']
        chosen_match = user_action['chosen_match']
        
        # Analyze which field differences matter to user
        field_analysis = {
            'date': {
                'suggested_score': suggested_match['scores']['date'],
                'chosen_score': chosen_match['scores']['date'],
                'difference': chosen_match['scores']['date'] - suggested_match['scores']['date']
            },
            'amount': {
                'suggested_score': suggested_match['scores']['amount'],
                'chosen_score': chosen_match['scores']['amount'],
                'difference': chosen_match['scores']['amount'] - suggested_match['scores']['amount']
            },
            'description': {
                'suggested_score': suggested_match['scores']['description'],
                'chosen_score': chosen_match['scores']['description'],
                'difference': chosen_match['scores']['description'] - suggested_match['scores']['description']
            }
        }
        
        # If reference numbers were available
        if 'ref_number' in suggested_match['scores']:
            field_analysis['ref_number'] = {
                'suggested_score': suggested_match['scores'].get('ref_number', 0),
                'chosen_score': chosen_match['scores'].get('ref_number', 0),
                'difference': chosen_match['scores'].get('ref_number', 0) - suggested_match['scores'].get('ref_number', 0)
            }
        
        # Determine which field was most important in user's decision
        most_improved_field = max(field_analysis.items(), key=lambda x: x[1]['difference'])
        
        # Store learning
        self._update_field_importance(
            payer=user_action['payer'],
            field=most_improved_field[0],
            importance_delta=most_improved_field[1]['difference']
        )
```

### 2. Adaptive Weight Learning

```python
def _update_field_importance(self, payer, field, importance_delta):
    """
    Learn which fields are most reliable for each payer
    """
    # Example: User consistently chooses matches with better descriptions
    # over matches with better ref_numbers for "ABC Corp"
    
    pattern_key = f"{payer}_{field}_importance"
    
    if pattern_key not in self.patterns:
        self.patterns[pattern_key] = {
            'payer': payer,
            'field': field,
            'importance_adjustments': [],
            'avg_adjustment': 0.0,
            'occurrence_count': 0
        }
    
    self.patterns[pattern_key]['importance_adjustments'].append(importance_delta)
    self.patterns[pattern_key]['occurrence_count'] += 1
    
    # Calculate average adjustment
    adjustments = self.patterns[pattern_key]['importance_adjustments']
    avg = sum(adjustments) / len(adjustments)
    self.patterns[pattern_key]['avg_adjustment'] = avg
    
    # If we have enough data (5+ occurrences) and consistent pattern
    if self.patterns[pattern_key]['occurrence_count'] >= 5:
        if abs(avg) > 0.1:  # Significant adjustment
            # Update ML model
            self._push_to_orchestrator({
                'rule_type': 'field_weight_adjustment',
                'payer': payer,
                'field': field,
                'weight_adjustment': avg,
                'confidence': self._calculate_weight(pattern_key)
            })
```
